# 계정 관리 — 개요

## 배경

[auth 도메인](../auth/overview.md)의 "후속 이슈"로 분리해뒀던 항목 중 계정 관리 화면을 구현한다. 지금은 직원 계정이 Flyway 시드 데이터로만 존재하고, 관리자가 화면에서 계정을 만들거나 바꿀 방법이 없다.

권한 관리 화면(계정별 메뉴 CRUD 권한 지정)은 이번 범위에서 제외하고 별도 스펙으로 다룬다.

## 범위

**포함:**
- 관리자가 계정을 검색/필터로 조회, 생성, 수정(이름/역할/활성상태/비밀번호 재설정), 비활성화, 하드 삭제하는 화면과 API
- 관리자가 직접 입력한 비밀번호로 계정을 생성 — 신규 계정은 다음 로그인 시 비밀번호 변경을 강제
- 관리자가 기존 계정의 비밀번호를 재설정하는 액션(재설정 시에도 다음 로그인 시 변경 강제가 다시 걸림)
- 본인 계정의 비활성화/삭제 차단, 마지막 남은 활성 계정의 비활성화/삭제 차단
- 이 화면 자체를 [auth 도메인](../auth/overview.md)의 `@RequiresPermission` 메커니즘으로 보호 (리소스 키 `accounts`)

**제외 (별도 이슈로 분리):**
- 권한 관리 화면 (관리자가 계정별 메뉴 CRUD 권한 지정) — 지금은 Flyway 시드로 대체
- 계정 잠금 / 브루트포스 방어 (auth 도메인에서도 YAGNI로 보류한 항목, 여기서도 동일)
