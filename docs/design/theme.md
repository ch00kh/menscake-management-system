# 시스템 테마 — 송편

ERP의 색 체계. 대한민국 송편에서 가져왔습니다.

시안(네 방향 비교, 실제 화면에 입힌 모습):
https://claude.ai/code/artifact/f8ca86c4-66fe-4307-b1ee-042b37236da7

---

## 1. 원칙

**주색은 쑥입니다.** 쑥송편의 초록. 채도를 낮게 눌러 하루 종일 봐도 눈이 편하도록 했습니다.
업무 시스템은 사용자가 8시간 보는 화면이라, 인상보다 피로도가 먼저입니다.

**어둠은 솔잎입니다.** 송편은 솔잎을 깔고 찝니다. 다크 모드의 바탕을 무채색 검정이 아니라
솔잎빛이 도는 어둠(`hue 155`)으로 잡았습니다. 검정보다 차갑지 않고, 야간 전표 작업에서
눈이 덜 부십니다.

**색은 일을 해야 합니다.** 장식으로 쓰지 않습니다. 주색은 액션(확정·저장·제출)과 활성 상태에만,
의미색은 상태 표시에만 씁니다. 나머지는 무채에 가까운 중립으로 둡니다.

## 2. 구조 — 축이 두 개입니다

```
              라이트                      다크
A · 쑥        아이보리 + 쑥 초록     →    솔잎 바탕 + 쑥 초록      (기본)
B · 치자      크림 + 치자 금색       →    솔잎 바탕 + 치자 금색
E · 백년초    연분홍 + 백년초 자홍   →    솔잎 바탕 + 백년초 자홍
```

- **팔레트 축** (`A | B | E`) — 사용자가 고릅니다. 기본은 A.
- **밝기 축** (`light | dark | system`) — 사용자가 고릅니다. 기본은 system.

**다크의 바탕은 세 팔레트가 공유합니다.** 주색만 팔레트를 따라갑니다.
그래서 다크 팔레트를 세 벌 만들 필요 없이 지반 한 벌 + 주색 토큰 교체로 끝납니다.

> 이전 시안의 `D · 솔잎`은 독립 선택지가 아니라 **모든 팔레트의 공통 다크 지반**이 됐습니다.
> 선택지에서 D가 사라진 이유입니다.

백년초를 쓰던 사람은 다크에서도 자홍입니다.

대안은 다크 주색을 쑥 초록으로 고정하는 것이었습니다. 다크 팔레트가 한 벌로 줄어 단순하지만,
같은 사람의 같은 시스템에서 밝기만 바꿨는데 브랜드색이 자홍 → 초록으로 갈아엎어집니다.
밝기는 밝기만 바꾸는 축이어야 합니다.

되돌리려면 `index.css`에서 `.dark.palette-chija` 와 `.dark.palette-baengnyeoncho` 의
`--primary` 선언만 지우면 `.dark` 의 쑥 초록이 그대로 상속됩니다.

### 3.5 파생 토큰

`--tab-strip` — 헤더·탭 스트립·사이드바 여백에 깔리는 면.

```css
background-color: color-mix(in oklab, var(--muted) 50%, var(--background));
```

`index.css`의 `@utility bg-tab-strip`이 이 값입니다. 하드코딩하지 마세요 —
팔레트가 바뀌면 자동으로 따라가야 합니다.

`--sidebar`는 `var(--background)`입니다. 플로팅 사이드바 카드를 컨텐츠와 같은 면으로
두기 위한 것이고, 나머지 `--sidebar-*`는 대응하는 본 토큰을 그대로 참조합니다.

## 4. 의미색 — 상태 표시

ERP는 상태 구분이 핵심입니다. 상태색은 **팔레트와 무관하게 고정**입니다.
사용자가 테마를 바꿨다고 "반려"의 색이 달라지면 안 됩니다.

| 상태 | 라이트 배경 / 글자 | 다크 배경 / 글자 |
|---|---|---|
| 승인완료 | `0.93 0.04 148` / `0.36 0.055 148` | `0.33 0.055 148` / `0.87 0.075 148` |
| 진행 | `var(--muted)` / `var(--muted-foreground)` | 동일 |
| 반려 | `0.94 0.045 25` / `0.45 0.13 27` | `0.35 0.075 22` / `0.86 0.09 25` |
| 보류 | `0.94 0.05 82` / `0.44 0.09 72` | `0.34 0.06 78` / `0.88 0.09 82` |

**예외 하나** — E 백년초에서는 "반려"를 주황(`hue 45`)으로 씁니다. 3.3의 이유와 같습니다.

## 5. 사용 규칙

- **주색은 아껴 씁니다.** 화면당 주 액션 하나. 확정·저장·제출 같은 되돌리기 어려운 동작에만.
  나머지 버튼은 `outline`이나 `ghost`.
- **색만으로 정보를 전달하지 않습니다.** 상태 배지는 색 + 글자를 함께 씁니다.
  색각 이상 사용자와 흑백 인쇄를 위해서입니다.
- **원시 색상값 금지.** `bg-blue-500` 같은 Tailwind 팔레트 색을 쓰지 않습니다.
  전부 시맨틱 토큰(`bg-primary`, `text-muted-foreground`)으로.
- **`dark:` 수동 보정 금지.** 토큰이 이미 테마별로 정의돼 있습니다.
  `dark:bg-gray-800` 같은 걸 붙이면 팔레트 전환이 깨집니다.
- **차트 색은 `--chart-1..5`.** dataviz 규칙상 차트 안에서는 CSS 변수가 아니라
  해석된 값이 필요할 수 있으니, 그때는 토큰 값을 읽어 넘깁니다.

## 6. 구현

### 6.1 지금 (백엔드 없이 완결)

`index.css`에 팔레트별 토큰 블록을 정의하고, `<html>`의 클래스 두 개로 조합합니다.

```html
<html class="palette-sugg dark">
```

- 팔레트: `palette-sugg` | `palette-chija` | `palette-baengnyeoncho`
- 밝기: `dark` (없으면 라이트)

`theme-provider.tsx`가 이미 밝기 축을 `localStorage` + `<html>` 클래스로 처리하고 있습니다
(`storageKey: "theme"`). 팔레트 축을 같은 방식으로 하나 더 붙입니다
(`storageKey: "theme-palette"`).

**첫 페인트 깜빡임(FOUC) 방지.** React가 마운트되기 전에 클래스가 붙어 있어야 합니다.
`index.html`의 `<head>` 끝에 인라인 스크립트를 둡니다.

```html
<script>
  try {
    var p = localStorage.getItem('theme-palette') || 'sugg'
    var t = localStorage.getItem('theme') || 'system'
    var dark = t === 'dark' || (t === 'system' &&
      matchMedia('(prefers-color-scheme: dark)').matches)
    document.documentElement.classList.add('palette-' + p)
    if (dark) document.documentElement.classList.add('dark')
  } catch (e) {}
</script>
```

### 6.2 나중 (백엔드 착수 후)

사용자별 테마를 기기 간에 유지하려면 서버에 저장해야 합니다.
컬럼은 **두 개로 나눕니다.**

```sql
account.theme_palette  varchar   -- 'sugg' | 'chija' | 'baengnyeoncho'
account.theme_mode     varchar   -- 'light' | 'dark' | 'system'
```

한 컬럼에 `'chija-dark'`처럼 합치면 조합이 곱으로 늘고, "시스템 설정 따름"을 표현할
자리가 없어집니다.

**localStorage는 그때도 계속 씁니다.** DB에서 읽으려면 로그인 API 응답을 기다려야 하는데,
그 사이 첫 페인트가 기본 테마로 나가서 매 접속마다 화면이 번쩍입니다. 역할을 나눕니다.

- `localStorage` — 첫 페인트를 위한 **즉시 적용용 캐시**
- DB — 기기 간 동기화의 **진실 공급원**. 로그인 후 값이 다르면 조용히 맞추고 캐시 갱신

즉 6.1은 임시방편이 아니라 최종 구조의 절반입니다. 나중에 버릴 코드가 아닙니다.

## 7. 폰트

**본문 — IBM Plex Sans KR** (`--font-sans`). 400 / 500 / 600 세 굵기.
**큰 제목 — 고운바탕** (`--font-serif`). 700 한 굵기.

Google Fonts CDN이 아니라 `@fontsource` 패키지로 **자체 호스팅**합니다. 사내 ERP는 외부망이
막혀 있을 수 있어 CDN 의존은 위험합니다.

### 7.1 어디에 무엇을 쓰나

| 토큰 | 서체 | 쓰이는 곳 |
|---|---|---|
| `--font-sans` | IBM Plex Sans KR | 본문 전부 |
| `--font-heading` | = `--font-sans` | shadcn 컴포넌트 제목 (카드 · 다이얼로그 · 시트 · 드로어 · Empty 등 10곳) |
| `--font-serif` | 고운바탕 | **세 곳만** — 페이지 제목, 사이드바 브랜드, 갤러리 소제목 |

`--font-heading`을 고운바탕으로 잡았다가 되돌렸습니다. 고운바탕은 **400과 700뿐**이라
`font-heading font-medium`(500)을 쓰는 shadcn 컴포넌트 제목이 전부 400 레귤러로 떨어져
본문과 굵기가 같아졌습니다. 명조는 큰 제목 세 곳에만 남기고, 컴포넌트 제목은 본문 서체의
500으로 위계를 줍니다.

⚠️ **`font-serif`는 굵은 굵기로만 쓰세요.** 700만 싣기 때문에 `font-normal`로 쓰면
브라우저가 700을 대신 씁니다. 한글 서브셋 한 벌이 CSS 94규칙 + 에셋 6MB라 안 쓰는 굵기는
싣지 않았습니다.

### 7.2 용량

한글 폰트는 용량이 관건이라 **세분화 서브셋**(`@font-face` 376개, 각각 `unicode-range`)을
씁니다. 브라우저가 화면에 실제로 쓰인 글자의 서브셋만 받습니다.

| | 값 |
|---|---|
| 실제 전송 (전표 화면 1장) | **23개 파일 24 KB** |
| CSS | 507 KB (gzip 161 KB) |
| dist 폰트 에셋 | 367개 파일 14 MB (디스크만, 전송 안 됨) |

대안이던 통짜 한글 파일(`korean-*.css`)은 CSS는 작지만 파일 하나가 500 KB라 첫 로드에
약 2 MB를 받습니다. 세분화 쪽이 훨씬 유리합니다.

CSS가 gzip 161 KB로 늘어난 것은 실제 비용입니다. 더 줄이려면 본문 600을 빼면 됩니다
(현재 쓰임이 적음).
