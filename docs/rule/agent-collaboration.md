# Agent Collaboration

## 작업 할당 (SSOT)

- 모든 작업 단위는 GitHub Issue로 관리한다. Issue = "무엇을 만들지"에 대한 단일 진실 공급원(SSOT).
- 에이전트는 자신에게 assign된 Issue만 작업한다. assign 안 된 이슈는 건드리지 않는다.

## 모호함 처리 — 가정 절대 금지

- **요구사항이 모호하면 추측·가정으로 진행하지 않는다.** "합리적으로 보이는 가정"도 예외 없이 금지한다.
- 반드시 해당 Issue에 질문 코멘트를 남기고, 응답이 올 때까지 작업을 중단하고 대기한다.
- 잘못된 가정으로 진행한 작업을 되돌리는 비용이, 질문하고 기다리는 비용보다 항상 크다.

## 작업 시작 전 체크리스트

1. `dev` 최신으로 pull
2. assign된 Issue 전체 정독
3. `docs/rule/` 컨벤션 문서 확인
4. git-convention 네이밍대로 `dev`에서 새 브랜치 생성

## 작업 종료 후 체크리스트 (PR 올리기 전)

1. 로컬 lint/test 통과 확인
2. 스스로 diff 리뷰 (불필요한 파일 변경 없는지)
3. PR 제목 = 커밋 컨벤션 형식, 본문에 `Closes #이슈번호` + 어떤 작업 단위로 생성됐는지 한 줄 요약
4. PR 올린 뒤 최소 1명 승인 대기 (git-convention의 PR 규칙 참조)

## 컨벤션 문서 자체가 SSOT

- `docs/rule/` 문서가 프로젝트 규칙의 SSOT다.
- 코드/PR에서 문서와 다른 방식을 발견해도 임의로 새 패턴을 만들지 않는다. 먼저 `docs/rule/`을 확인하고, 문서에 없는 규칙이 필요하면 문서 추가를 먼저 제안한다.
