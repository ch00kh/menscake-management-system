# 컨벤션

**같은 것을 두 사람이 다르게 부르지 않게 하는 것.** 그게 목적의 전부입니다.

개발을 에이전트가 수행하므로 규칙은 **판단을 요구하지 않아야** 합니다 —
읽고 나서 "그래서 어느 쪽이지"가 남으면 규칙이 아닙니다.

| 문서 | 언제 보나 |
|---|---|
| [core.md](core.md) | 이름을 붙일 때. 표기 · 케이스 · 값 표기 · 식별자 설계 · 문서 규칙 |
| [git.md](git.md) | 브랜치를 따거나 커밋할 때. **에이전트가 저장소에 무엇을 해도 되는지** |
| [stack.md](stack.md) | 코드를 쓸 때. 패키지 구조 · API 규격 · 물리 네이밍 · 마이그레이션 · 테스트 |

`core.md` 와 `git.md` 는 **스택과 무관**합니다. 백엔드를 다른 걸로 바꿔도 그대로입니다.
`stack.md` 는 Java + Spring Boot + PostgreSQL 을 전제합니다.

결정의 근거와 기각한 대안은 [adr/](../adr/) 에 있습니다.

## 재검토 조건

규칙은 전부 확정됐고 미결이 없습니다. 다만 **어떤 조건이 생기면 다시 열 만한지**를
같이 적어둡니다 — 그게 없으면 6개월 뒤에 뒤집어도 되는지 알 수 없습니다.

| 규칙 | 지금 | 다시 열 만한 조건 |
|---|---|---|
| 축약어 ([core](core.md) 1.2) | 거의 금지, 허용 목록만 | 맞춰야 할 외부 시스템·양식이 생기면 |
| 시각 저장 ([core](core.md) 3.1) | UTC 저장 + KST 표시 | 서버·DB가 전부 사내이고 국내 전용이 확정되면 |
| PK ([core](core.md) 4.1) | `bigint` 자동증가 | 여러 거점·오프라인에서 ID 선생성이 필요해지면 UUID v7 |
| 삭제 ([core](core.md) 4.3) | 논리 삭제 기본, 개인정보만 예외 | — 예외 테이블은 도메인마다 지정 완료 |
| 브랜치 ([git](git.md) 1장) | 환경 브랜치 (`main` 운영 / `dev` 개발) | 동시에 여러 버전을 유지해야 하면 |
| 코드값 ([stack](stack.md) 3.4) | `varchar` + `CHECK` | — 값 추가가 잦아 이 선택을 한 것입니다 |
| 영속성 ([stack](stack.md) 1.4) | 엔티티에 JPA 애노테이션 | 도메인 로직이 JPA 때문에 뒤틀리기 시작하면 분리 |

바꿀 때는 **이유를 같이 적습니다.** 그리고 해당 ADR 항목에 `대체됨`을 답니다.
